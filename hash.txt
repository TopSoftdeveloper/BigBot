# Distributed Hashcat 7.1.1 — Manual setup for 6+ PCs

For your Bitcoin `wallet.dat` password recovery, I recommend manual keyspace distribution using Hashcat's `--skip` and `--limit` options.

This works with Windows and Linux computers, does not require a central server, and prevents PCs from testing the same passwords when the ranges are calculated correctly.

Each computer uses the same hash and attack configuration, but receives a different starting position and workload.

### Requirements

- Hashcat 7.1.1 on every PC, ideally the same version.
- Working GPU drivers and Hashcat backends.
- Your verified Bitcoin hash in `1.txt`.
- A unique Hashcat session name for each PC.
- A record of which ranges have finished.

You do not need to distribute `wallet.dat`. Hashcat mode `11300` uses the extracted hash.

For security, restrict the hash to machines you own or trust. Keep `wallet.dat` on your primary recovery machine.

## 2. Verify the hardware

On Windows:

```
.\hashcat.exe -I
.\hashcat.exe -b -m 11300
```

On Linux:

```
./hashcat.bin -I
./hashcat.bin -b -m 11300
```

Record each machine's benchmark in H/s. Your earlier result of approximately 978 H/s was from a very small search and may not represent sustained performance.

## 3. Choose a fixed mask

For example, for passwords containing lowercase letters, uppercase letters, digits, and symbols, with exactly six characters:

```
?a?a?a?a?a?a
```

All computers must use the identical mask. When distributing one search, avoid `--increment`: different password lengths should be treated as separate jobs.

### Calculate Hashcat's keyspace

Windows:

```
.\hashcat.exe -m 11300 -a 3 --keyspace '?a?a?a?a?a?a'
```

Linux:

```
./hashcat.bin -m 11300 -a 3 --keyspace '?a?a?a?a?a?a'
```

Important: Hashcat's `--keyspace` output is not necessarily the total number of password combinations. It reports a base-loop size specifically intended for splitting work with `--skip` and `--limit`. Use the returned value, rather than calculating `95^6` yourself.&#x20;

## 5. Start Hashcat on each computer

Using the hypothetical ranges above, the Windows commands would look like this.

PC 1 (Windows):

```
.\hashcat.exe -m 11300 -a 3 --session=btc-pc1 --skip 0 --limit 100000 1.txt '?a?a?a?a?a?a'
```

PC 2 (Linux):

```
./hashcat.bin -m 11300 -a 3 --session=btc-pc2 --skip 100000 --limit 100000 1.txt '?a?a?a?a?a?a'
```

PC 3 (Windows):

```
.\hashcat.exe -m 11300 -a 3 --session=btc-pc3 --skip 200000 --limit 100000 1.txt '?a?a?a?a?a?a'
```

Continue assigning the remaining ranges to PCs 4, 5 and 6.

Do not use these example ranges for your real search until you calculate its actual keyspace.

## 6. Monitor progress

While Hashcat is running, press `s` in its terminal to display status.

Check these fields:

```
Status...........: Running
Speed.#01........: 12500 H/s
Recovered........: 0/1
Progress.........: ...
```

The speed shown is only an example.

Keep a simple record of each PC's session, `skip`, `limit`, status, and completed range. Do not assign an unfinished range to another PC unless you're deliberately restarting or redistributing it.

On newer Hashcat versions, some combinations of range options and session restoration have limitations. Check restore support for your exact 7.1.1 build before relying on it for multi-day runs.&#x20;

## 7. How much faster is six-PC recovery?

If every PC sustains the same performance, six PCs can approach six times the throughput of one PC.

For different GPUs, their speeds add approximately:

\\[ H\_{\text{total}}=H_1+H_2+\cdots+H_6 \\]

However, even six fast computers may be insufficient for a long, completely unknown password containing letters, digits and symbols.

For example, an eight-character password using 95 printable ASCII characters has:

\\[ 95^8 = 6{,}634{,}204{,}312{,}890{,}625 \\]

possible combinations. Exhaustive recovery could still be impractical.
